# Milestone 4 — ElevenLabs voice implementation plan

> **For agentic workers:** Use subagent-driven-development or executing-plans. User has authorized implementation; no additional design approval is needed.

**Goal:** A real ElevenLabs conversation can check records and create/correct the same saved draft, with review-card-only approval.

**Architecture:** React uses the current `@elevenlabs/react` provider and SDK. Local FastAPI issues temporary signed conversation access bound to the current app session. A separate FastAPI gateway exposes only four authenticated webhook tools; SQLite stores expiring conversation bindings and existing versioned drafts.

**Tech stack:** Existing React/TypeScript/Vite/Tailwind, Python/FastAPI/SQLite; ElevenLabs React SDK. No LangChain.

**Spec:** `landlord-repair-assistant-build-plan.md`, Milestone 4, plus the user's latest request.

## Constraints and review focus

- Preserve Hearth design and all M2/M3 checks; no voice approval, dispatch, or confirmed booking.
- Secrets live in root `.env`, never Vite variables, transcript, source, or logs.
- Tunnel only gateway port 8001; main API 8000 and frontend 5173 stay local.
- Authenticate webhook secret plus opaque, expiring binding token. Bind once to ElevenLabs' system conversation ID; never accept a model-selected app session.
- Correct the bound draft only, with explicit expected revision. Cancellation, stale revisions, wrong-session IDs, expired/revoked bindings fail closed.
- Polling must not replace unsaved form edits. End the conversation before enabling approval; retain saved drafts after error/disconnect/reload.
- Test absent configuration, provider failure, microphone denial, stale writes, concurrent/replayed calls, and gateway route isolation.
- Use temporary test databases. Preserve the user's existing SQLite records. This directory has no Git repository, so no worktree or commits.

## Shared browser/backend contract

- `GET /api/voice/config` → `{available: boolean, message: string, max_duration_seconds: number}`.
- `POST /api/voice/access` body `{session_id, mode: 'voice'|'text', draft_id: string|null, expected_revision: number|null}` → `{voice_session_id, signed_url, expires_at, max_duration_seconds, dynamic_variables: {secret__hearth_binding, hearth_context}}`. The supplied draft and revision must match the current active saved draft; new draft uses null/null. Backend chooses the actual session context.
- `POST /api/voice/{voice_session_id}/bind` body `{session_id, conversation_id}` → `{ok:true}`; ensures SDK connection ID agrees with webhook's system conversation ID.
- `POST /api/voice/{voice_session_id}/end` body `{session_id}` → `{ok:true}`. Revokes the binding. Starting another conversation revokes the old one.
- Voice errors use `{error_code, message, draft?}` with appropriate HTTP status. No upstream secrets or raw upstream body returned.
- Existing `GET /api/sessions/{session_id}` supplies the persisted draft and activity while connected and after ending.
- SDK uses signed URL with explicit WebSocket transport for both voice and text; text mode sends the conversation text-only override.

## Public gateway/tool contract

All four `POST /voice/tools/{tool_name}` routes require `X-Hearth-Webhook-Secret` (ElevenLabs workspace secret), `X-Hearth-Binding` (dynamic variable `secret__hearth_binding`), and `X-ElevenLabs-Conversation-Id` (dynamic variable `system__conversation_id`). No other business or docs routes on this gateway.

- `lookup_property`: `{query:string, unit_label:string}`. Return actual property choices, unique matched unit only when unambiguous, status, current bound draft and guidance.
- `check_open_jobs`: `{unit_id:string, category:'plumbing'|'electrical'|'general', issue_summary:string}`. Return actual duplicate jobs and current draft.
- `lookup_maintenance_context`: `{unit_id:string, category:'plumbing'|'electrical'|'general'}`. Return policy/history/approved contractors and current draft.
- `prepare_repair_draft`: `{draft_id:string|null, expected_revision:integer, fields:object}`. New uses null/0; corrections use the exact returned ID/revision and only changed editable fields. Editable fields follow existing `DraftFields`. Backend rechecks property/unit, eligibility, duplicates and safety using existing draft workflow. Return `{draft, events}`. No approval/session/status fields accepted.
