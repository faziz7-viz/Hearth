# Milestone 4 backend implementation report

Implemented local voice access/config/bind/end routes and a separate `backend.app.voice_gateway:app` with exactly four authenticated tool routes and no docs or business API routes. Provider access requests use the backend key, a five-second timeout, and `include_conversation_id=true`. The adapter accepts the provider conversation ID in the response or signed URL, rejects missing/mismatched IDs or non-ElevenLabs WebSocket URLs, and redacts provider failures.

SQLite now stores expiring voice capabilities as hashes, with session owner, prebound conversation ID, revocation, grounded property/unit, and bound draft ID. New access revokes old access; End is idempotent. Authentication runs before gateway body parsing and again inside each business transaction. Current/error gateway drafts omit the local app session capability. The local app retains its full draft contract.

Shared draft creation/edit helpers let capability validation and draft mutation commit atomically. A unique property/unit lookup must precede unit record reads and any new/changed location. Tools use the existing record checks and validation; revisions, cancellation, approval, concurrent creation, stale corrections, and unrelated draft IDs fail closed. Voice never creates work orders. Main approval rejects active unexpired voice bindings until the conversation ends. Read failures have one bounded retry and safe factual activity when SQLite remains writable.

Configuration uses root `.env` through pinned `python-dotenv==1.2.4`; settings hide private credentials in repr. Maximum call duration is clamped to 60–600 seconds. Missing configuration leaves the form available with a clear 503 response to Start. Voice access is restricted to local Host/Origin addresses. Root `.env.example` contains only blank placeholders.

Verification: `backend/.venv/bin/python -m pytest -q` → 128 passed, 4 subtests passed (2026-10-22, includes the root agent's concurrently added configuration tests). The voice test file has 35 cases covering provider failures, authorization, malformed unauthenticated input, binding ownership, duplicate/safety/contractor checks, same-draft correction, stale/cancelled/approved drafts, creation races/replays, restart persistence, access races, expiry/revocation, transaction rollback, route isolation, and secret/capability redaction.

Rulings: prebind only provider-issued conversation IDs instead of first-webhook claiming; fail closed if provider response cannot prove the ID. Keep incomplete drafts allowed, but never allow guessed non-null location IDs. End-before-Approve is enforced by both browser and backend. A new conversation after terminal work omits the old draft from model context.

No existing servers were stopped or restarted by this agent. Tests used isolated temporary databases; the live database was not modified. No authenticated ElevenLabs requests or account changes were made. Live conversation, browser microphone, external HTTPS reachability, and SDK/provider response compatibility remain integration/live acceptance checks for the parent agent.

During a failing environment-duration test, pytest's dataclass repr exposed the locally generated webhook secret in tool output. The parent agent was informed immediately to rotate it before tunnel use. No ElevenLabs API key was present. Sensitive settings repr is now disabled and environment tests use an isolated nonexistent `.env` path.

Integration fix: the parent agent found the system Python's bundled CA store was unavailable. Provider HTTP now uses `truststore.SSLContext(ssl.PROTOCOL_TLS_CLIENT)` (already pinned dependency) with both certificate and hostname verification enabled. Regression test first failed for absent TLS context, then passed. A real unauthenticated GET to the official ElevenLabs signed-access endpoint reached HTTP 401 using system trust; no API key was sent. Full suite remained 128 passed, 4 subtests passed after this fix. This connectivity check is not evidence of a successful authenticated conversation.
